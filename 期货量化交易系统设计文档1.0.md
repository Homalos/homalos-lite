## 一、总体架构设计：事件驱动 + 数据流解耦

参考TqSdk的架构，整个系统采用“基于网络协作的组件设计”，核心思想是**以数据流连接各组件**，行情网关负责实时行情和历史数据，交易网关负责连接期货公司交易系统，两者统一通过Diff协议对下游提供标准化服务。内部通信采用Python `asyncio.Queue`通道实现组件间的单向数据流传输。

#### 2.1.3 `core/diff.py` — DIFF 协议增量合并

```python
from typing import Any, Dict, List, Optional

def apply_diff(data: Dict[str, Any], diffs: List[Dict[str, Any]]) -> None:
    """
    将 diff 列表合并到 data 字典中。
    diff 对象格式: {"path": ["quotes", "SHFE.cu2305", "last_price"], "value": 68801}
    """
    for diff in diffs:
        path = diff.get("path", [])
        value = diff.get("value")
        if not path:
            continue
        # 按路径导航到父对象
        obj = data
        for key in path[:-1]:
            if key not in obj:
                obj[key] = {}
            obj = obj[key]
        # 设置最终值
        if value is None:
            # 删除键
            if isinstance(obj, dict) and path[-1] in obj:
                del obj[path[-1]]
        else:
            obj[path[-1]] = value
```

#### 2.1.4 `core/data_series.py` — K线/Tick序列生成

```python
from collections import deque
from typing import Deque, Dict, List, Tuple
from dataclasses import dataclass
import time

@dataclass
class Bar:
    symbol: str
    datetime: float
    open: float
    high: float
    low: float
    close: float
    volume: int
    duration: float  # 周期秒数

class TickSequence:
    """简单的 Tick 序列缓存"""
    def __init__(self, max_len: int = 1024):
        self._ticks: Deque[dict] = deque(maxlen=max_len)

    def push(self, tick: dict) -> None:
        self._ticks.append(tick)

    def get_last(self) -> dict:
        return self._ticks[-1] if self._ticks else {}

class KlineSeries:
    """实时合成 K 线序列（由 tick 驱动）"""
    def __init__(self, symbol: str, duration: float, max_len: int = 500):
        self.symbol = symbol
        self.duration = duration
        self._bars: Deque[Bar] = deque(maxlen=max_len)
        self._cur_bar: Optional[Bar] = None

    def on_tick(self, tick: dict) -> Optional[Bar]:
        """收到 tick，更新当前 bar，若 bar 闭合则返回闭合的 bar"""
        ts = tick["datetime"]
        price = tick["last_price"]
        volume = tick.get("volume", 0)
        # 计算当前 bar 的理论结束时间
        bar_start = (ts // self.duration) * self.duration
        bar_end = bar_start + self.duration
        
        if self._cur_bar is None:
            # 开始新 bar
            self._cur_bar = Bar(
                symbol=self.symbol,
                datetime=bar_start,
                open=price,
                high=price,
                low=price,
                close=price,
                volume=volume,
                duration=self.duration
            )
            return None
        
        if ts < bar_end:
            # 仍在同一 bar 内
            self._cur_bar.high = max(self._cur_bar.high, price)
            self._cur_bar.low = min(self._cur_bar.low, price)
            self._cur_bar.close = price
            self._cur_bar.volume += volume
            return None
        else:
            # 当前 bar 闭合，push 并创建新 bar
            closed_bar = self._cur_bar
            self._bars.append(closed_bar)
            # 新建 bar
            self._cur_bar = Bar(
                symbol=self.symbol,
                datetime=bar_start,
                open=price,
                high=price,
                low=price,
                close=price,
                volume=volume,
                duration=self.duration
            )
            return closed_bar

    def get_bars(self, n: int = None) -> List[Bar]:
        bars = list(self._bars)
        if self._cur_bar:
            bars.append(self._cur_bar)
        if n is not None:
            bars = bars[-n:]
        return bars
```

#### 2.1.5 `core/api.py` — 中央调度器（CoreApi）

这是整个系统的神经中枢，负责：

- 持有 `_data` 快照
- 通过 `TqChan` 连接行情和交易网关
- 实现 `wait_update()` 事件驱动
- 提供行情查询、交易、订阅、风控等统一接口

```python
import asyncio
import time
from typing import Any, Dict, List, Optional, Set
from collections import deque
from .channel import TqChan
from .diff import apply_diff
from .data_series import KlineSeries, TickSequence

class CoreApi:
    def __init__(self, md_gateway, td_gateway, backtest_engine=None):
        # 数据快照（所有业务数据）
        self._data: Dict[str, Any] = {
            "quotes": {},       # symbol -> quote dict
            "positions": {},    # symbol -> list of position dicts
            "account": {}       # 账户信息
        }
        # 待处理的差异数据包
        self._pending_diffs: deque = deque()
        # 已订阅合约
        self._subscriptions: Set[Tuple[str, str]] = set()  # (symbol, type)
        
        # 数据通道（连接网关）
        self._md_gateway = md_gateway
        self._td_gateway = td_gateway
        # 回测引擎（如果提供）
        self._backtest = backtest_engine
        
        # 策略管理器（在注册策略时可用）
        self.strategy_manager = None
        
        # 风控
        from risk.manager import RiskManager
        self.risk_manager = RiskManager()
        
        # 序列存储：{ (symbol, duration_seconds) -> KlineSeries }
        self._kline_serials: Dict[tuple, KlineSeries] = {}
        self._tick_seq: Dict[str, TickSequence] = {}
        
        # 启动数据处理协程
        self._task = None

    async def _run(self):
        """不断从网关接收数据并放入 pending_diffs"""
        while True:
            data = await self._md_gateway.recv()  # 假设网关提供异步 recv
            if data:
                self._pending_diffs.append(data)
                # 驱动 kline 合成
                self._on_data(data)

    def _on_data(self, data: dict):
        """处理接收到的原始数据，进行 kline 合成等"""
        # 如果包含 tick，驱动相应 KlineSeries
        if "ticks" in data:
            for symbol, tick in data["ticks"].items():
                if symbol not in self._tick_seq:
                    self._tick_seq[symbol] = TickSequence()
                self._tick_seq[symbol].push(tick)
                # 驱动所有该 symbol 的 kline series
                for (sym, dur), kline in self._kline_serials.items():
                    if sym == symbol:
                        closed = kline.on_tick(tick)
                        if closed:
                            # 可将 closed bar 推送给策略等，或在 _data 中更新
                            pass

    def start(self):
        if self._task is None:
            self._task = asyncio.ensure_future(self._run())

    async def wait_update(self, timeout: float = 0.5) -> bool:
        """
        事件驱动核心：等待直到收到至少一个数据包或超时。
        返回 True 表示有新数据并已合并，False 表示超时。
        """
        if self._backtest:
            return await self._backtest.step()  # 回测模式
        deadline = time.time() + timeout
        while not self._pending_diffs and time.time() < deadline:
            await asyncio.sleep(0.001)  # 极短让出，保持低延迟
        # 合并所有 pending diffs
        while self._pending_diffs:
            diff = self._pending_diffs.popleft()
            if isinstance(diff, list):
                apply_diff(self._data, diff)
            else:
                # 其他格式处理
                pass
        return bool(self._pending_diffs)  # 返回是否有新数据（注意已消费，所以始终False？改）
        # 修改：在合并前记录是否有 pending，合并后返回
        # 实际应改为：
        # had_data = bool(self._pending_diffs)
        # 然后合并...
        # return had_data

    # ---------- 行情查询 API ----------
    def get_quote(self, symbol: str) -> dict:
        return self._data.get("quotes", {}).get(symbol, {})

    def is_changing(self, quote: dict, field: str = "last_price") -> bool:
        """简单判断：比较当前值和上一次值（需实现缓存）"""
        # 简化实现，始终返回 True，生产需记录 last_checked
        return True

    # ---------- 订阅订阅 ----------
    async def subscribe(self, symbols: List[str]):
        for s in symbols:
            self._subscriptions.add((s, "quote"))
        await self._md_gateway.subscribe(symbols)

    # ---------- 交易 API ----------
    async def insert_order(self, order_req: dict) -> Optional[str]:
        # 风控预检查
        if not self.risk_manager.check_pre_trade(order_req, self._data["account"]):
            return None
        # 发送给交易网关
        return await self._td_gateway.insert_order(order_req)

    def get_position(self, symbol: str = None) -> list:
        if symbol:
            return self._data.get("positions", {}).get(symbol, [])
        return list(self._data.get("positions", {}).values())

    def get_account(self) -> dict:
        return self._data.get("account", {})
```

**设计要点**：

- **`wait_update`机制**：使用事件驱动替代固定间隔轮询。发现`_pending_diffs`有数据立即中止等待循环、合并数据，然后返回让用户代码继续执行，实现“数据到达即处理”的低延迟语义。
- **不可变快照模型**：所有数据存储在`_data`字典中，数据收到时增量合并（DIFF协议），而非全量替换，大幅减少网络流量和内存开销。

### 2.3. 风控模块 (risk) — 多层纵深防御

参考vn.py等成熟系统的设计，风控模块作为独立的管道拦截器插入数据流。

#### 2.3.1 `risk/manager.py` — 可插拔风控管理器

python

```python
from typing import Callable, List
from enum import Enum

class RiskLevel(Enum):
    PRE_TRADE = "pre_trade"

class RiskRule:
    def __init__(self, name: str, level: RiskLevel, check: Callable, action: str = "reject"):
        self.name = name
        self.level = level
        self.check = check  # 检查函数: (order_req, account) -> bool
        self.action = action  # "reject" / "warn"

class RiskManager:
    def __init__(self):
        self._rules: List[RiskRule] = []

    def add_rule(self, rule: RiskRule):
        self._rules.append(rule)

    def remove_rule(self, name: str):
        self._rules = [r for r in self._rules if r.name != name]

    def check_pre_trade(self, order_req: dict, account: dict) -> bool:
        for rule in self._rules:
            if rule.level == RiskLevel.PRE_TRADE:
                if not rule.check(order_req, account):
                    if rule.action == "reject":
                        return False
        return True
```

风控核心功能：
- **预交易风控**：检查保证金充足率、持仓集中度、单笔最大下单量等硬性指标；
- **执行中风控**：监控订单成交情况，处理滑点与部分成交；
- **事后风控**：生成交易报告，统计盈亏和风险暴露。

### 2.4. 策略模块 (strategy)

参考TqSdk“不预设用户策略模型”的设计原则，不提供策略类模板，只提供通用性资源和能力，用户可任意组合API函数实现策略。

#### 2.4.1 `strategy/base.py` — 轻量策略基类

```python
from abc import ABC, abstractmethod
from typing import List, Optional
import asyncio

class BaseStrategy(ABC):
    """策略基类 —— 提供生命周期和钩子，但不强制继承"""
    def __init__(self, api, name: str, symbols: List[str]):
        self.api = api
        self.name = name
        self.symbols = symbols
        self._running = False
        self._task: Optional[asyncio.Task] = None

    @abstractmethod
    async def on_init(self):
        """初始化：订阅、指标准备等"""
        ...

    @abstractmethod
    async def on_tick(self, tick: dict):
        """tick 到来时的处理"""
        ...

    async def on_bar(self, bar):
        """K线闭合时触发（可选实现）"""
        pass

    async def on_order(self, order: dict):
        """订单状态变化回调（可选）"""
        pass

    async def start(self):
        self._running = True
        self._task = asyncio.ensure_future(self._run_loop())

    async def stop(self):
        self._running = False
        if self._task:
            self._task.cancel()
            self._task = None

    async def _run_loop(self):
        await self.on_init()
        while self._running:
            await self.api.wait_update()
            # 遍历监听的合约，如果 quote 有变化则触发 on_tick
            for symbol in self.symbols:
                quote = self.api.get_quote(symbol)
                if quote and self.api.is_changing(quote):
                    await self.on_tick(quote)
```

实际集成时，在 `CoreApi.__init__` 中若提供 `backtest`，则在 `wait_update` 中调用 `backtest.step()` 来推进时间，并更新 `api._data`。

回测核心规则：
- 如果订阅了Tick数据，quote由Tick生成，更新频率与Tick一致；
- 如果未订阅Tick但订阅了K线，quote由K线生成，更新频率与K线周期一致；
- 如果既无Tick也无K线（或K线周期大于分钟线），则自动订阅分钟线来生成quote；
- `wait_update`每次最多推进一个行情时间，确保事件时序正确；
- 回测结束时抛出`BacktestFinished`异常通知用户。

## 三、低延迟响应策略

### 3.1 事件驱动替代固定间隔轮询

传统量化系统常用`time.sleep()`或固定频率循环来等待新数据，引入不必要的延迟。TqSdk使用`wait_update`机制，直接利用asyncio事件循环的特性：一旦WebSocket收到数据包并放入`_pending_diffs`，`wait_update`内部的等待循环便会立即中止，完成数据合并后立即返回，从而做到“数据到达即处理”。本系统完全复用这一模式。

### 3.2 异步+同步结合

| 场景                     | 模式           | 实现方式                                                     |
| ------------------------ | -------------- | ------------------------------------------------------------ |
| 行情数据获取（K线/Tick） | 异步非阻塞     | `await api.get_kline_serial()`，内部通过异步Channel从网关拉取 |
| 订单执行/撤单            | 同步（低延迟） | 数据包写入`send_chan`后立即返回，真正的网络发送由异步协程在后台完成 |
| WebSocket实时推送        | 异步           | FastAPI原生支持异步WebSocket                                 |
| REST API查询             | 异步           | FastAPI async路由 + 内部await调用                            |

### 3.3 协程任务池 — 多策略并行

每个策略作为独立的`asyncio.Task`运行在主事件循环中，利用Python asyncio的协程调度实现“伪并行”，避免多线程的GIL竞争和复杂的锁同步问题。

```python
async def main():
    api = CoreApi(account=TqSim(), auth=TqAuth("user", "pass"))
    api.setup_connection(CtpMdGateway(...), CtpTdGateway(...))

    manager = StrategyManager(api)
    manager.register(StrategyA(api, "strategy_a", ["SHFE.cu"]))
    manager.register(StrategyB(api, "strategy_b", ["DCE.i"]))

    await manager.start_all()
    # 所有策略在同一个事件循环中并行运行
    await asyncio.Event().wait()  # 永久运行
```

## 五、集成Go组件增强性能

对于需要处理大并发行情流的生产环境，可以在上述Python架构的基础上集成Go组件作为旁路加速：

- **alpha-trade-gateway**：独立Go进程，负责CTP直连，通过gRPC向Python核心层提供行情和交易服务，利用Golang的协程池模型应对高并发场景，使用`sonic`/`easyjson`替代标准库JSON编解码以降低CPU开销；
- **alpha-market-service**：对标tqsdk的行情数据服务，提供标准化的多市场数据接入能力。

Python核心层通过gRPC客户端调用Go服务，保持异步非阻塞的调用模式，同时Go的Worker Pool模型能有效避免Python GIL在高并发时的性能瓶颈。

## 六、总结

本系统架构的核心设计理念可归纳为以下几点：

| 特性          | 实现手段                                                     |
| ------------- | ------------------------------------------------------------ |
| 低延迟        | `wait_update`事件驱动替代固定间隔轮询；CTP行情/交易双通道分离 |
| 高扩展性      | TqChan管道解耦组件；多行情源代理模式；策略管理器动态注册     |
| 统一API       | CoreApi整合行情订阅、交易接口、账户管理于一体                |
| 异步+同步结合 | asyncio协程实现异步IO；订单执行同步返回避免竞态              |
| Web GUI       | FastAPI + WebSocket提供REST API和实时数据推送                |
| 模块化        | 分层架构：网关层/核心层/策略层/风控层/展示层独立松耦合       |
| 多市场源      | MultiMarketGateway代理模式 + Go组件旁路加速                  |
| 增量更新      | DIFF协议：完整快照 + 后续增量diff合并，降低带宽              |
| 多策略        | 每个策略独立asyncio.Task运行，策略管理器统一管控             |
| 回测引擎      | TqBacktest模式替换数据源，Tick/K线双模回测，代码统一         |

---

在原生 TqSdk 中，策略确实没有一个强制性的“基类”，用户可以直接用 `api.wait_update()` + 各种行情/交易函数，以最自由的方式编织逻辑。TqSdk 的这一设计理念是把“策略怎么做”完全交给用户，框架只提供原子能力，避免了抽象层带来的额外心智负担。

而在我们设计的系统中加入 `BaseStrategy` 和 `StrategyManager`，并非要推翻这种自由，而是为了解决**“把单策略自由组合放大到多策略、多市场、产品化运行时”必然遇到的工程问题**。  

具体原因如下：

### 1. 多策略并行与生命周期管理
实际生产环境往往同时运行多个独立策略（比如不同品种、不同周期、不同逻辑），它们需要被统一**启动、停止、监控状态**。  
如果没有一个策略抽象，策略只是一堆自由函数或异步循环，框架无法知道“哪些任务属于同一个策略单位”，更无法在 Web GUI 上点击“停止策略A”而不影响策略B。  
`BaseStrategy` 提供了一个轻量的**生命周期协议**（`start/stop/_run_loop`），让框架可以像管理服务一样管理策略实例。

### 2. Web GUI 的可观测性与控制
我们希望 Web 界面能展示“当前运行策略列表”、“策略状态（运行中/已停止）”、“策略最近日志/信号”等。这要求策略以**可查询的对象**的形式注册到系统中。  
`StrategyManager` 作为注册中心，记录每个策略的元信息，内部通过 `asyncio.Task` 安全地控制协程，使前端通过 REST/WebSocket 就能对任意策略进行启停、参数调整（如果设计允许）等操作，而不是去手动 `kill` 进程或者找不到对应任务。

### 3. 与风控、回测的松耦合对接
一个真正的风控模块需要能在策略**提交订单前**拦截，或者事后统计每个策略的风险暴露。如果策略只是零散函数，订单流无从归属，风控就难以区分“策略A的多单”和“策略B的空单”。  
有了基类，风控检查时可以传递 `strategy_id`，事后也能按策略维度生成盈亏报告。  
回测引擎同样受益：在回测模式下，`StrategyManager` 可以用回测时间驱动来统一推进所有策略的 `on_tick`/`on_bar`，保证时序严格一致，这是散装异步协程很难做到的。

### 4. 扩展性但非刚性
我们的 `BaseStrategy` 设计得极为**轻薄**——它只定义了几个可选钩子（`on_init`, `on_tick`, `on_bar`, `on_order`），而不强迫用户填充所有方法，也不规定必须怎样下单（一切仍通过注入的 `api` 对象自由调用）。  
用户依然可以像写原生 TqSdk 代码一样在 `on_tick` 里自由组合逻辑，完全不影响灵活性。同时，不继承 `BaseStrategy` 的“裸协程”也一样可以跑，只是无法享受全局管理带来的便利。  
也就是说，**基类是一份可选的管理契约，而不是约束**。

### 总结
在 TqSdk 那种**单用户、单策略、研究导向**的场景下，无基类风格是最优解。而在我们面向 **“专业多策略期货交易系统”** 的目标下，引入 `BaseStrategy` 和 `StrategyManager` 是用极小的抽象成本，换来了多策略运行、Web 管理、风控嵌入、回测兼容等工程能力的质变。 

我们完全尊重 TqSdk “策略即函数”的哲学，并把它保留在基类的更底层——`CoreApi` 仍然提供所有原子函数，让高级用户随时绕过基类直接使用。这种弹性设计正是我们希望传递给您的：**框架提供轨道，但不限制你如何奔跑。**
